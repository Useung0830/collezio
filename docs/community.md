# 커뮤니티 구현 현황

## 완료한 단계

1. 게시글·댓글·좋아요 타입, Firestore 규칙과 인덱스
2. 게시글 작성, 최신순 목록과 상세 조회
3. 사진 첨부, 검증, 업로드 실패 정리
4. 작성자 게시글 수정·삭제와 삭제 정리 재시도
5. 댓글 작성·수정·삭제, 게시글 좋아요·취소
6. 내 게시글·댓글의 실제 데이터 조회
7. 예시 데이터 제거, 접근성·실패 복구 점검과 전체 회귀 테스트

## 화면과 데이터

| 화면                  | 동작                                                        |
| --------------------- | ----------------------------------------------------------- |
| `/community`          | 공개 최신순 피드, 20개씩 더보기                             |
| `/community/new`      | 로그인 후 작성, 제목 100자·본문 5,000자 제한                |
| `/community/[postId]` | 공개 상세·댓글, 작성자 수정·삭제, 로그인 사용자 댓글·좋아요 |
| `/posts`              | 로그인한 사용자의 글·댓글, 최신순 20개씩 더보기             |

- 사진은 JPG·PNG·WebP, 장당 5MB 이하, 총 10장이다. 새 사진 업로드 후 글을 저장하고 제거한 사진을 정리한다.
- 댓글은 1,000자까지 작성하며 최신순으로 조회한다. 최초 작성 후 5분 이내에 본인 댓글만 수정할 수 있다. 시간 제한은 Firestore 서버 규칙에서도 검증한다. 삭제에는 시간 제한이 없다.
- 댓글은 재시도할 때 같은 문서 ID를 사용한다. 이미 같은 내용이 저장되었다면 추가 문서를 만들지 않는다.
- 좋아요는 `communityPosts/{postId}/likes/{uid}`와 게시글 `likeCount`를 트랜잭션으로 함께 변경한다. 원하는 선택 상태를 전송하므로 동일 요청의 반복 실행으로 횟수가 늘지 않는다. 본인 게시글 좋아요는 차단한다.
- 저장 응답이 유실되거나 동일 요청이 경합하면 서버의 저장 결과를 확인한다. 결과를 확인하지 못하면 성공으로 표시하지 않는다.
- 글·댓글 수정은 수정 시각의 초·나노초 버전을 비교하여 다른 탭의 변경을 덮어쓰지 않는다.
- 계정별 조회 키와 인증 UID 재검증으로 계정 전환 시 이전 사용자의 목록·좋아요·댓글 입력 상태가 섞이지 않게 한다.
- 내 댓글은 현재 원문 제목을 함께 조회하고 삭제된 게시글의 댓글을 제외한다. 숨겨진 항목도 원래 페이지 커서에 포함해 다음 페이지를 조회할 수 있다.
- 프로필이 있으면 댓글에 실제 닉네임을 표시한다. 프로필이 없거나 조회에 실패하면 `회원`으로 표시한다.

## 삭제와 실패 복구

게시글 삭제와 `communityPostDeletions/{postId}` 작업 기록 생성을 하나의 트랜잭션으로 실행한다. 공개 글이 제거된 뒤 댓글·좋아요를 100개씩 삭제하고 사진을 정리한다. 모두 성공하면 작업 기록을 삭제한다.

작업 기록은 작성자만 읽을 수 있다. 중단된 경우 작성자가 기존 상세 주소를 열면 `삭제 정리 다시 시도`가 표시된다. 작업 중인 게시글 ID 재생성과 새 사진 업로드는 차단한다. 삭제 대상은 서버에서 조회하여 오프라인 캐시의 빈 결과를 정리 완료로 오인하지 않는다.

정리 작업은 브라우저에서 실행한다. 사용자가 창을 닫으면 자동으로 계속 실행되지 않는다. 글 수정 후 제거한 사진 정리가 실패하거나 저장 결과를 확인할 수 없는 업로드가 남으면 안내를 표시하며, 현재 서버의 자동 파일 정리 작업은 없다.

## 현재 범위와 장기 설계의 차이

이 구현은 현재 저장소의 Firebase 클라이언트 SDK·Security Rules 구조를 따른다. [Firebase 백엔드 설계](backend/firebase-backend-design.md)는 장기 목표도 포함하며, 아래 항목은 이번 단계에 구현하지 않았다.

- Callable Functions, App Check, 이메일 인증·계정 상태·차단 관계에 따른 커뮤니티 권한 제어
- 신고·숨김·알림과 삭제 원문 보관 정책
- 삭제 위치에 남기는 tombstone 문서와 서버 댓글 수 집계: 현재 글과 댓글은 실제 삭제한다.
- 조회 수의 24시간 중복 방지 집계: `viewCount`는 기존 필드로 유지하며 미구현 조회 수를 화면에 표시하지 않는다.
- 서버에서 계속 실행하는 사진·하위 문서 정리 작업

## 검증과 배포

```bash
npm run check
npm run test:unit
npx firebase emulators:exec --config firebase.e2e.json --project demo-collezio --only auth,firestore,storage "node --test tests/integration/*.test.mjs"
npm run test:e2e
```

통합 테스트와 브라우저 테스트는 별도의 새 에뮬레이터에서 실행한다. 브라우저 테스트가 데모 프로젝트 설정으로 프로덕션 빌드를 생성한다. 실제 배포 빌드는 대상 환경 설정으로 다시 생성해야 한다.

실제 Firebase 적용에는 `firestore.rules`, `firestore.indexes.json`, `storage.rules`가 필요하다. 공유 규칙 파일에는 채팅·상품 권한도 포함되어 있으므로 배포 시 통합된 최신 파일을 사용한다. 이 단계의 검증은 로컬 에뮬레이터 기준이며 운영 규칙이나 인덱스를 배포하지 않았다.
